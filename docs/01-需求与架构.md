# VisionQC 需求说明与技术架构 V1

## 1. 项目定位

VisionQC 是面向工业零件图片的质检业务平台：图片批次管理 → 人工缺陷标注 → 审核工作流 → 质量统计与追踪。目的是展示完整全栈能力（Java + Spring Boot + MySQL + Vue 3），**不做 AI 模型、不做相机控制**。

## 2. 角色

| 角色 | 核心职责 |
|------|----------|
| ADMIN | 用户/角色/设备/缺陷分类/批次管理、分配质检任务、全局统计 |
| INSPECTOR | 我的任务、图片查看、矩形框标注、提交审核、查看驳回原因 |
| REVIEWER | 待审任务、查看标注、通过/驳回（原因必填）、审核历史 |

权限全部由后端（Spring Security）验证，前端隐藏按钮仅是体验优化。

## 3. 技术架构

```
┌─────────────────────────── 浏览器 ───────────────────────────┐
│  Vue 3 (Vite) + Element Plus + Pinia + Vue Router + ECharts  │
│  Fabric.js 标注工作台（归一化坐标存储）                          │
└──────────────┬───────────────────────────────┬───────────────┘
               │ axios（JSON + Session Cookie）│
┌──────────────▼───────────────────────────────▼───────────────┐
│                 Spring Boot 3 (单体，:8080)                   │
│  Controller ─► DTO ─► Service(事务边界/状态机/乐观锁) ─► Repository(JPA)  │
│  Spring Security: Session 认证 + HTTP防火墙 + 方法级权限        │
│  文件服务: 暂存→落盘→原子move, SHA-256 去重                     │
└──────────────┬───────────────────────────────┬───────────────┘
               │                               │
       MySQL 8/9 (Flyway 迁移)        本地磁盘 vqc-storage/
       11 张业务表 + 索引/唯一约束     {batchId}/{uuid}.ext 与元数据分离
```

### 3.1 关键技术选型与理由

| 选型 | 为什么 | 备选方案 |
|------|--------|----------|
| Session 认证（非 JWT） | 单体部署、同源前端，Session + Cookie 最简单安全，登出即失效 | JWT（无状态但撤销困难、需处理刷新，单体场景无收益） |
| Spring Data JPA + 乐观锁 | 快速 CRUD；@Version 解决并发审核；复杂统计用原生 SQL | MyBatis（SQL 全手写，CRUD 重复劳动多） |
| Flyway | 版本化 schema，可重复迁移，交付演示可靠 | JPA ddl-auto（生产不可控） |
| 归一化坐标 DECIMAL(8,6) | 缩放/分辨率变化不漂移 | 像素坐标（会漂移） |
| 服务端 UUID 文件名 | 防路径穿越、防重名覆盖 | 用户文件名（穿越/注入风险） |
| 不引入 Redis/MQ/Docker | 单机演示够用；引入会掩盖核心考点 | —（Phase 4 评估后再定） |

### 3.2 分层规范

```
Controller  只做参数校验(@Valid)+权限注解+调 Service，返回 DTO
Service     业务规则、状态机、事务边界(@Transactional)
Repository  JPA 接口 + 少量 @Query
Entity      与 DTO 严格分离，Entity 不出 Service 层
```

## 4. 核心业务模块（对应任务书第六节）

1. 用户与权限（注册/登录/登出/资料，BCrypt）
2. 设备管理（CRUD + 启停 + 关联批次）
3. 生产批次（CRUD + 进度/审核统计）
4. 图片管理（单/多上传、分页、预览、SHA-256 去重、类型/大小校验、一致性保障）
5. 缺陷标注（Fabric.js 矩形框，保存/恢复）
6. 审核工作流（状态机 + 权限矩阵 + 乐观锁）
7. 审核历史与审计日志（只增表，不含敏感信息）
8. 质量统计看板（ECharts，指标口径见 03 文档）
9. 报表导出（CSV，UTF-8 BOM + 公式注入防护）

## 5. 三个技术难点（对应任务书八/九/十）

- **并发审核**：JPA @Version，冲突 HTTP 409，集成测试双事务竞争。
- **查询性能**：查询 A（多条件分页质检记录）与查询 B（设备+日期范围不良率），EXPLAIN 前后对比留档 `docs/08-查询优化报告.md`。
- **文件一致性**：暂存目录 → DB 提交 → 原子 rename；失败补偿删除暂存文件；定时任务清理孤儿文件（Phase 2 实现状态字段方案，Phase 4 加补偿任务）。
